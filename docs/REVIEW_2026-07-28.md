quirc sync), covering three dimensions in parallel: **security** (crypto,
vault, entropy, untrusted-input parsing, IPC surfaces), **code quality**

audit's findings were re-verified as genuinely fixed in the current tree.

## Executive summary

Overall the repository is in strong shape:

- **Security:** no critical or high findings. The frozen vault format matches
  its spec exactly (encrypt-then-MAC, constant-time MAC verification before
  decrypt, downgrade-resistant MAC-covered header, atomic save). The
  passphrase is verifiably interactive-only across CLI/GUI/ARexx. The #110
  quirc memory-safety fixes are present and complete on the exact call path
  used.
- **Documentation:** unusually accurate. CLI reference matches the ReadArgs
  template character-for-character; all settings, tooltypes, defaults, and
  vault-format fields verified; all 103 internal links resolve; mkdocs nav /
  docs2guide `PAGES` / `userdocs/` contents agree exactly.
- **Code quality:** four high-severity items — a data-loss path in
  `vault_save`, a stack-smash risk from unbounded catalog strings, a
  security-state bug on hidden commodity start, and a CI gap that leaves the
  GUI uncompiled on PRs — plus a tail of medium/low items.

## High-severity findings

### H1. `vault_save` error path can destroy both the original vault and the temp copy

`src/core/vault.c:358-361`. If the first `rename(tmp, path)` fails, the
original vault is deleted (the AmigaOS "Rename won't overwrite" retry); if
the retry also fails (target recreated concurrently, delete-protect bit,
volume error), `remove(tmp)` deletes the only surviving copy of every
account. A transient I/O error becomes unrecoverable secret loss.

**Fix:** once the original is gone, never delete the temp file — leave it in
place and return an error identifying it as recoverable.

**Fixed:** the retry-failure path now keeps the temp file and returns a new
`VAULT_ERR_TMPKEPT`; both front-ends tell the user their accounts survive in
the `.tmp` file (new catalog strings 146/147), Vault-and-Passphrases.md
documents the recovery, and a regression test locks in that the kept `.tmp`
is a complete, loadable vault.

### H2. Unbounded `sprintf` of translated catalog strings into fixed stack buffers

`src/cli/main.c:366, 388, 395` (`prompt[160]`), `:423` (`prompt[64]`),
`:621, 630` (`prompt[96]`). `sprintf(prompt, "%s ", MSG(...))` copies
translator-controlled text with no bound. The English strengthen-prompt is
already ~117 of 160 bytes; German/French translations routinely run 20–40 %
longer — a stack smash on a no-MMU 68000, in exactly the re-key/passphrase
flows. `tools/check_catalog.py` lints placeholders but not lengths, and
`AmiAuth.cd` declares no maxlens.

**Fix:** bounded copies; declare FlexCat maxlens (`(id//maxlen)`) in the
catalog description; add a length check to the linter.

**Fixed:** all six sites now go through a truncating `prompt_text()` helper
into a single `PROMPT_CAP` (160) buffer, and `tools/check_catalog.py` fails
the build when any of the six prompt strings (in the `.cd` or any `.ct`)
exceeds the cap — so a translation can no longer smash the stack, and an
overlong one is caught at lint time rather than shown truncated.
**Residual (open):** `src/gui/main.c` has the same class of pattern with
format arguments (`sprintf(title, MSG(...), ...)` at e.g. `:340, :619,
:963, :1386`) — each site needs its buffer audited against its format args;
tracked as follow-up, not covered by this fix.

### H3. Hidden commodity start never sets `encrypted` — ARexx UNLOCK/LOCK/STATUS misreport

`src/gui/main.c:2016-2018` vs `:2318-2341`. The deferred-unlock branch
(`CX_POPUP=no`) calls `vault_load(&v, path, NULL)` and sets `deferred = 1`,
but `encrypted` is only set inside `gui_open_vault()` (`:1044`), which this
branch skips. Against a hidden start with an encrypted vault, ARexx `UNLOCK`
— the one command you'd use in that state — returns "always-unlocked"
without unlocking, and `STATUS`/`LOCK` misreport the security state.

**Fix:** `encrypted = (vault_load(...) == VAULT_ERR_LOCKED)` in the deferred
branch.

**Fixed:** exactly that — `VAULT_ERR_LOCKED` now sets `encrypted` in the
deferred branch (a missing vault on first run correctly leaves it 0), so
ARexx `UNLOCK` prompts and `STATUS`/`LOCK` report the true state.

### H4. PR CI never compiles the GUI or the m68k quirc objects

`.github/workflows/ci.yml:103-112`. The `m68k-build` job runs only
`make m68k` (CLI). `src/gui/main.c`, `src/amiga/qrimage.c`,
`src/amiga/arexx.c`, and the m68k build of vendored quirc
(`build/qr-m68k/*.o`, built only by the `gui` target) are first
cross-compiled at release-tag time. A PR that breaks GUI compilation merges
green and fails the release.

**Fix:** add `make gui` to the m68k CI job.

**Fixed:** the `m68k-build` job now cross-builds the GUI (and with it
`qrimage.c`, `arexx.c`, and the m68k quirc objects) on every PR that touches
`src/`.

### H5. ARexx `TIMELEFT` is not gated by `arexxgetcode`, contradicting docs and intent

`src/gui/main.c` ~`:2303-2311` vs `:2293`. The `GETCODE` handler checks both
`v.unlocked` and the `arexxgetcode` pref (with a comment showing the gating
is deliberate); `TIMELEFT` checks only `v.unlocked`. With `arexxgetcode off`
scripts can still probe account existence/validity (RC 10 vs a result)
through a port the user believed restricted.
[ARexx-Port.md](../userdocs/ARexx-Port.md) (lines 46, 59–62) documents the
intended gated behaviour — this is a code bug, not a doc bug.

**Fix:** add the same pref check to the `TIMELEFT` case.

**Fixed:** `TIMELEFT` now carries the same `arexxgetcode` gate as `GETCODE`
(same RC, so a script can't probe why it failed), matching what
ARexx-Port.md already documented.

## Medium-severity findings

### Security-adjacent

- **M1. Unauthenticated KDF iteration count → DoS.** `src/core/vault.c:410-416`
  runs PBKDF2 before the MAC check; a tampered header with
  `iterations = 0xFFFFFFFF` is effectively a permanent hang on a stock 68000
  (~14 iters/s). `KDF_MAX_ITERATIONS` (4,000,000, `vault.h:35`) already
  exists as policy. Fix: reject `iterations == 0 || iterations >
  KDF_MAX_ITERATIONS` as `VAULT_ERR_FORMAT` before deriving keys
  (reader-side only; frozen format untouched).
  *Fixed:* `vault_load` rejects `iterations == 0 || > KDF_MAX_ITERATIONS` as `VAULT_ERR_FORMAT` before deriving keys, and `vault_create`/`vault_set_passphrase` clamp at creation so writers stay within reader bounds; covered by new tests.
- **M2. HMAC finals/one-shots never zeroize key material.**
  `src/core/hmac.c:44-56, 103-115, 162-174` (+ one-shots): `ctx->opad` is
  key⊕0x5c (trivially invertible); `inner`/`outer`/ctx never wiped. PBKDF2
  wipes its own state but calls the one-shot `hmac_sha1` per iteration, so
  passphrase-derived pads survive on the stack after every unlock. Also
  unwiped: `chacha20_xor`'s `state[16]`/`block[64]`
  (`src/core/chacha20.c:56-87`), `otp_truncate`'s `mac[]`
  (`src/core/otp.c:40-71`), `src/core/uri.c` decoded-secret buffers on error
  paths (`:190-204, 254-303`), sha one-shot ctxs. Undermines the otherwise
  careful zeroization discipline on a machine without memory protection.
  *Fixed:* all three HMAC finals scrub `inner`/`outer`/the whole ctx (no caller reuses a finalised ctx); `chacha20_xor` scrubs `state`+`block`; `otp_truncate` scrubs the MAC; sha one-shots scrub their ctx; `otpauth_parse` wipes the partial account on error and `otpauth_build` its Base32 buffer on every exit.
- **M3. Cross-session nonce distinctness rests entirely on `DateStamp`.**
  `src/amiga/random.c:38,153`: `g_calls` is process-static, so the
  documented "monotonic counter so the nonce never repeats" only holds
  within one run. On a deterministic emulator cold-booted from a frozen RTC,
  two runs could seed the DRBG identically and reuse a ChaCha20 nonce under
  the same key (ciphertext XOR leaks plaintext XOR). Within the documented
  threat envelope, but [VAULT_FORMAT.md](VAULT_FORMAT.md) §nonce and
  [SECURITY.md](SECURITY.md) overstate the guarantee. Fix: persist a save
  counter (e.g. fold the prior vault's stored nonce into the entropy pool),
  or soften the doc wording.
  *Fixed:* both front-ends fold the previous vault file's header+MAC (which includes the last nonce) into the entropy pool before each save (`amiga_stir_file`), chaining successive nonces across cold-boot-identical runs; SECURITY.md/VAULT_FORMAT.md wording aligned with the actual guarantee (the residual first-ever-save case is documented, not overclaimed).
- **M4. SNTP anti-spoofing is thin; offset applied unbounded.**
  `src/amiga/sntp.c:68-83`, `src/core/clock.c:86-94`: `connect()` filters
  only by (spoofable) source IP, and the echo check uses `time(NULL)` —
  guessable to the second — so a LAN attacker can inject an arbitrary offset
  that is then trusted as `CLOCK_SYNCED` (green) with no magnitude bound.
  Fix: use a random 64-bit transmit-timestamp nonce as the anti-replay
  token; optionally bound the accepted delta (the audit's rationale for no
  bound — RTC-less machines — allows a *wide* finite bound).

  *Fixed (nonce half):* the transmit-timestamp fraction now carries 32 random bits and the reply must echo both seconds and fraction — blind forgery odds 2^-32 per attempt. The unbounded offset is retained deliberately (RTC-less machines need arbitrary corrections, per CLOCK.md).
### Correctness / UX

- **M5. Copy can copy the previously selected account's code.**
  `src/gui/main.c:2412-2418, 2487-2493, 2648`: `curcode` refreshes only on
  the 1 Hz tick; select-then-Copy within a tick pastes a valid-looking OTP
  for the wrong account. Fix: refresh `curcode` from `g_code[sel]` whenever
  `sel` changes.
  *Fixed:* any selection change (row click or cursor key) refreshes `curcode` and the detail pane immediately, before the same event batch's Copy runs.
- **M6. Selection highlight and `sel` diverge across hide/show.**
  `src/gui/main.c:1631-1632`: `win_show` hardcodes `LISTBROWSER_Selected, 0`
  while `sel` persists across Exchange hide/show and idle auto-lock —
  highlight shows row 0, Copy/Edit/Remove/Show-QR act on the old `sel`.
  *Fixed:* `sel` is now file-scope and `win_show` seeds `LISTBROWSER_Selected` from it (clamped to the account count), so highlight and acted-on row can't diverge.
- **M7. Copied OTP survives on the clipboard after quit.**
  `src/gui/main.c:2664-2700`: the 30 s auto-wipe only runs while alive;
  quitting inside the window (menu, `CXCMD_KILL`, Ctrl-C) leaves the code on
  the clipboard indefinitely. Fix: clear-if-ours during cleanup.
  *Fixed:* cleanup clears the clipboard if the copy is inside its 30 s window and the clipboard still holds our clip (same clear-if-ours check as the tick); GUI-Guide.md updated.
- **M8. `clock_now_utc` 32-bit signed arithmetic — UB at 2038, garbage codes pre-epoch.**
  `src/core/clock.c:16-21`: `(uint64_t)((long)now + off)` on 32-bit `long`
  overflows (UB) at 2038 and sign-extends a negative sum (unset RTC +
  negative offset) into a huge counter. Fix: `int64_t` arithmetic, clamp
  negatives to 0.

  *Fixed:* `int64_t` arithmetic with negative results clamped to 0.
### Resource handling / robustness

- **M9. timer.device / MsgPort / IORequest leaked every CLI run.**
  `src/amiga/random.c:59-86`: the "OS reclaims it at exit" comment is wrong —
  Exec has no resource tracking; each CLI invocation leaks the port +
  IORequest and bumps timer.device's open count until reboot. Fix: explicit
  `CloseDevice`/`DeleteIORequest`/`DeleteMsgPort` from both front-ends'
  teardown.
  *Fixed:* `amiga_entropy_cleanup()` closes the device/IORequest/port and scrubs the pool+DRBG state; called from both front-ends' teardown; the wrong "OS reclaims it" comment corrected.
- **M10. SNTP receive can hang forever on stacks ignoring `SO_RCVTIMEO`.**
  `src/amiga/sntp.c:61-63, 76`: `setsockopt` return ignored, no
  `SBTC_BREAKMASK` — one lost UDP packet blocks `recv()` with no Ctrl-C
  escape on AmiTCP-lineage stacks. Fix: `WaitSelect()` with timeval + break
  mask.
  *Fixed:* `WaitSelect()` with a 5 s timeval and a `SIGBREAKF_CTRL_C` break mask replaces the ignored `SO_RCVTIMEO`.
- **M11. CLI blocks unkillably if the GUI dies with a forwarded request queued.**
  `src/amiga/guiport.c:48-49`: `WaitPort(reply)` ignores `SIGBREAKF_CTRL_C`.
  Note: naive abort is worse (the GUI holds pointers into the CLI's stack
  frame) — either warn-and-keep-waiting on `Wait(portsig | CTRL_C)`, or move
  the request struct off the stack.
  *Fixed:* `Wait(portsig | SIGBREAKF_CTRL_C)` warn-and-keep-waiting loop (aborting is unsafe: the GUI holds pointers into the CLI's frame) with a localizable notice; documented in CLI-Reference.md.
- **M12. `win_show` leaks the gadget tree on window-object failure.**
  `src/gui/main.c:1738-1741, 1755-1756, 1717`: unlike the modal dialogs, the
  main-window path leaks `layoutobj` if `NewObject(WINDOW_GetClass(),...)`
  fails, and a Show retry after failed `WM_OPEN` overwrites `winobj` without
  disposing the old one.

  *Fixed:* the window-object failure path disposes the layout tree (cascades to children), and a failed `WM_OPEN` disposes `winobj` before any retry rebuilds it.
### Conventions / build / test

- **M13. CLI error exit code 2 invisible to AmigaDOS scripts.**
  `src/cli/main.c` (e.g. `:483, :613, :657, :1039`): AmigaDOS convention is
  WARN=5/ERROR=10/FAIL=20 with default `FAILAT 10`; `return 2` never stops a
  script, yet scripting with always-unlocked vaults is a supported use-case
  (the ReadArgs failure path already returns 20). Fix: map to
  `RETURN_ERROR` (10) on Amiga; keep 1/2 on host.
  *Fixed:* the Amiga `main` maps 1/2 → `RETURN_ERROR` (10) at its single exit; ReadArgs failure stays 20; host keeps 1/2; CLI-Reference.md exit-code table updated.
- **M14. No header dependency tracking in the Makefile.**
  `Makefile:104, 110, 120, 165`: rules depend only on `.c` files — editing
  `vault.h`, `crypto_dispatch.h`, `quirc_internal.h`, or generated
  `catalog_strings.h` rebuilds nothing, so `make test` can pass against a
  stale binary. Related: `$(BUILD)/asm-test-sha1` (`:255`) has only an
  order-only dep on the asm. Fix: `-MMD -MP` + `-include`, or header
  wildcards on the link rules.
  *Fixed:* header wildcards (`CORE_HDRS` etc.) added as prerequisites to the whole-program link rules, the qr object pattern rules, and `asm-test-sha1` (now with real source deps instead of order-only).
- **M15. No malformed-QR regression coverage.** `tests/test_qr.c` exercises
  only well-formed fixtures; the #110 `quirc_extract`/`quirc_flip`/
  `quirc_resize` bugs came from malformed input and would regress
  undetected. Fix: hostile fixtures and/or a deterministic pixel-fuzz loop,
  ideally under ASan on the host build.
  *Fixed:* `run_qr_hostile_tests` — structured degenerate images plus 200 rounds of seeded (xorshift32) pixel/hole/stripe corruption over a real QR; every decode must return a defined code and leave the output NUL-terminated.
- **M16. Vault header-level error paths untested.** `tests/test_vault.c`
  misses: truncated file (`vault.c:382`), bad magic/version (`:390`),
  cipher/kdf mismatch (`:399`), `payload_len` vs file-size mismatch
  (`:403`), `count > VAULT_MAX_ACCOUNTS` (`:160`), `secret_len >
  OTP_MAX_SECRET` (`:193`), trailing garbage (`:209`), and the digits-range
  check (`:183-187`) added by audit commit `d89831a`. All are two-line
  additions with the existing `write_raw_vault` harness.

  *Fixed:* tests added for every listed branch (truncation, bad magic/version, cipher/kdf mismatch, length mismatch, iteration bounds, count/secret_len caps, trailing garbage, digits range).
## Low-severity findings

- **L1.** `src/gui/main.c:283` opens graphics.library at 37 but uses
  V39 `ObtainBestPenA`/`ReleasePen` (`:361, :377`); open at 39 (GUI floor is
  OS 3.0 anyway).
  *Fixed:* opens at 39.
- **L2.** `src/gui/main.c:302-319, 409-419, 2696-2697`: `timer_open`/
  `clip_open` partial-failure leaks — cleanup gated on `have_*` flags, so a
  half-initialized open is never released.
  *Fixed:* both now undo exactly what they allocated on any partial-failure path (`clip_open` reuses `clip_close` for this).
- **L3.** `src/gui/main.c:846`: GUI passphrase entry drops Latin-1 codes
  (0xA0–0xFF) the CLI's raw read accepts — such passphrases silently can't
  unlock via the GUI. Accept `code >= 0xA0`. Related interop cliff: GUI
  passphrase buffers are 128 bytes (`:950, :1033`) vs the CLI's 256
  (`src/cli/main.c:420, 607`) — a 128–255-char passphrase set via CLI can't
  be entered in the GUI (fails safe). Standardise the capacity.
  *Fixed:* Latin-1 codes ≥0xA0 now accepted; GUI passphrase/confirm buffers (and the mask-display buffer) bumped to 256 to match the CLI.
- **L4.** `src/amiga/random.c:192-204`: if `SetMode(RAW)` fails the
  passphrase is read echoed while `*`s also print — return an error instead.
  Host twin: `src/cli/main.c:226-231` leaves the terminal no-echo on SIGINT.
  *Fixed:* `amiga_read_passphrase` now refuses (returns -1) if RAW mode can't be entered, instead of reading in an echoing mode; the host's `read_passphrase` restores terminal echo via a SIGINT handler before re-raising, so a Ctrl-C during the prompt no longer leaves the shell stuck in no-echo mode.
- **L5.** `src/amiga/arexx.c:81`: non-Rexx messages dropped without
  `ReplyMsg()` (teardown path replies everything; receive path should too).
  *Fixed:* both `arexx_receive` and `arexx_close` now reply every message, using a plain `ReplyMsg()` (not the RexxMsg-field-touching `arexx_reply`) for anything that fails `IsRexxMsg`.
- **L6.** `src/amiga/qrimage.c:96, 158`: `CopyMem()` on overlapping regions
  in row-compaction (third-party CopyMem patches need not honour overlap) —
  use a forward byte loop. Also `:163`: palette read `cregs[buf[i]]` can
  index past `PDTA_NumColors` on malformed deep images — clamp the pen.
  *Fixed:* row compaction now uses a shared `compact_rows` forward byte-copy helper (safe regardless of any `CopyMem` overlap quirk); the palette lookup clamps the pen index to `PDTA_NumColors - 1`.
- **L7.** `src/core/clock.c:70-94`: SNTP parse accepts a zero transmit
  timestamp (RFC 4330 requires rejecting it) → `CLOCK_SYNCED` with offset
  ≈ −now from a broken server.
  *Fixed:* `clock_ntp_parse_response` rejects a reply whose transmit timestamp is zero/pre-epoch.
- **L8.** `src/core/uri.c:206-208`: `digits=7` silently downgrades to 6
  (codes never validate); inconsistent with rejecting bad `algorithm=`, and
  the vault format accepts 6–8.
  *Fixed:* `digits=` now accepts 6-8 (matching the vault format/GUI) and rejects anything else outright, same policy as `algorithm=`.
- **L9.** Stack-budget notes (not bugs today): SHA-512 chain is ~1.3–1.4 KB
  core-only stack per code (`sha512.c:36-38` `w[80]` = 640 B); GUI's ~292 B
  `otp_account` locals are safe only because of `__stack = 32768`
  (`gui/main.c:85`). Worth a static `w[]` or a written stack budget.
  *Fixed (SHA-512 part):* `sha512_compress`'s `w[80]` is now `static`, off the stack entirely. The GUI's `__stack = 32768` remains the documented safety margin for its own locals.
- **L10.** `src/cli/main.c:548, 564, 474-475`: `atol`/`atoi` accept garbage
  silently (`OFFSET banana` persists 0) — use `strtol` with end-pointer
  checks. Also `:676, :857-859`: `try_forward`'s reply buffer and `cmd_qr`'s
  `uri[512]` (full otpauth URI incl. secret) are static BSS never zeroized.
  *Fixed:* `OFFSET`/`NUDGE` now parse via a new `parse_long` (`strtol` + end-pointer check) and report a new `MSG_CLI_BAD_NUMBER` on garbage input; `try_forward`'s reply buffer and `cmd_qr`'s `uri`/`modules`/`ascii` buffers are zeroed before every return.
- **L11.** `src/gui/main.c:1977`: `HotKey()`/`CxObjError` unchecked — a
  malformed `CX_POPKEY` yields a hotkey-less commodity with no diagnostic
  (worst with `CX_POPUP=no`). Also `:1792-1799`: `gui_do_show` returns
  success when `win_show` returned NULL (ARexx `SHOW` reports RC 0 with no
  window); `:569-575`: a mid-list `AllocListBrowserNode` failure desyncs
  row↔account indices (OOM edge).
  *Fixed:* `HotKey()`'s result and `CxObjError` are checked, with a new `MSG_GUI_BAD_POPKEY` diagnostic on failure; `gui_do_show` now returns failure when `win_show` itself fails; `build_nodes` fails closed (drops all nodes built so far) on any `AllocListBrowserNode` failure rather than leaving a row/account-index mismatch.
- **L12.** Defense-in-depth: `vault_add`/`serialize_payload`
  (`vault.c:262-268, 128-147`) trust caller-bounded `otp_account` fields;
  `src/core/drbg.c:48-53` accepts an empty seed (deterministic DRBG if
  upstream entropy fails silently).
  *Fixed:* `vault_add` now rejects `secret_len > OTP_MAX_SECRET` and non-NUL-terminated `issuer`/`label` before copying the account in. The DRBG's empty-seed behaviour is left as-is (changing it risked the SP 800-90A KAT vectors for an unreachable path — the real call site always passes a full 20-byte digest) but is now explicitly documented as a caller contract in `drbg.h`.
- **L13.** Build/CI nits: `-Wextra` missing from `M68K_CFLAGS`
  (`Makefile:21`); `catalog-lint` skipped on direct pushes to main
  (`ci.yml:34`); `.PHONY` omissions (`dist`, `guide`, `asm-tests`, …);
  m68k quirc rule hardcodes flags (`Makefile:167`); qrcodegen's 53 live
  `assert()`s → `abort()` in the shipped binary (no `-DNDEBUG` — decide
  deliberately and record it).
  *Fixed:* `-Wextra` added to `M68K_CFLAGS` (verified zero new warnings across CLI/GUI/asm-tests); `catalog` added to the direct-push filter loop; `.PHONY` now lists every phony target; the qr-host/qr-m68k object rules derive from `$(CFLAGS)`/`$(M68K_CFLAGS)` (with `-w` appended, which reliably overrides prior `-W...` flags) instead of a separately-hardcoded flag set; qrcodegen's `assert()`s are deliberately kept active, with the reasoning recorded in THIRDPARTY.md (it only ever encodes already-validated internal data, so a firing assert means a genuine encoder bug — better to abort loudly than ship a silently-corrupted QR of an account secret).
- **L14 (info).** The CLI→GUI `AAP_QR` forward (`src/cli/main.c:854` →
  `src/gui/main.c:2201`) renders the full secret-bearing `otpauth://` URI
  for any local caller while unlocked — consistent with the documented
  no-memory-protection threat model; noted for completeness.
  *No action:* as noted, this is inherent to the documented no-memory-protection threat model, not a defect.
